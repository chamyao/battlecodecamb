# cbs: the Cambridge Battlecode 2026a simulator

`sim/` is a headless C++20 re-implementation of the official engine (pip
package `cambc` 3.0.5, engine 1.0.3). It is checked against the engine by
replaying traced games line by line (`oracle/`, below); every rule settled that
way is recorded in `docs/ENGINE_FINDINGS.md`. Where the rules text and the
binary disagree, the binary wins and the finding says so.

In line with `docs/STRATEGY.md`, fuel is part of the game state, not an
afterthought: every bot call is priced and the per-turn budget is enforced
with the engine's suspension semantics.

## Layout

| Piece | Files | What it is |
| --- | --- | --- |
| Constants | `src/constants_gen.cpp` (generated by `tools/gen_constants.py` from `oracle/fixtures/engine_constants.json`) | Champion/camp/item/consumable designs and game settings, exact float bit patterns |
| Geometry | `include/cbs/bitboard.h`, `src/bitboard.cpp` | 100x100 bitboards, symmetric shadowcasting, reachable tiles, distance fields, shapes; bit-for-bit equal to the engine's host functions |
| Map | `include/cbs/map.h`, `src/map.cpp` | `.map26a` decoder, camp groups, bush clusters, precomputed 17x17 vision windows (radius 8 and 6) per tile |
| Rules | `include/cbs/game.h`, `src/game.cpp` | Full game state and rules: draft, round/turn structure, movement, combat, all champions, camps, capture/respawn, gems/altars/locks, items, consumables, wards, vision, death/recall, win and tiebreak |
| Bot API | `include/cbs/api.h`, `src/api.cpp` | One method per engine host import, same arguments, records and error codes, evaluated from one bot's perspective (hidden information enforced here) |
| Fuel | `include/cbs/fuel.h`, `src/fuel.cpp` | Price table (pluggable) and per-turn budgets |
| Runner | `include/cbs/runner.h`, `src/runner.cpp`, `src/coro.cpp` | Plays a match: each bot instance (one draft bot per team, one per champion) is a stackful coroutine |
| Policies | `include/cbs/bots.h`, `src/bots.cpp` | Built-in `starter` (port of the official starter bot) and `idle` |
| Tools | `tools/replay.cpp`, `tools/bench.cpp` | Differential replayer; throughput benchmark |
| Python | `python/cambsim.cpp`, `python/example.py` | pybind11 module `cambsim` |

Build: `cmake -S sim -B sim/build && cmake --build sim/build -j` (the Python
module is built when `pybind11` is importable). Tests: `ctest --test-dir
sim/build` (geometry vs engine probes, map decoding vs the engine's dump).

## Writing a policy

A policy is ordinary C++ that sees the game only through `cbs::Api`:

```cpp
class MyPlayer : public cbs::Player {
  cbs::BotBody make_bot(int team, int champ) override {
    return [](cbs::Api& api) {
      for (;;) {                          // one loop per bot instance, like a real bot
        if (api.champ() < 0) { /* draft: api.draft_champion(...) */ }
        else { /* play: api.champion(...), api.move_to(...), ... */ }
        api.end_turn();                    // yield the rest of this turn
      }
    };
  }
};
cbs::Match match(cbs::load_map("maps/00elkring.map26a"), a, b);
cbs::GameResult r = match.run();
```

`TurnPlayer` adapts a one-call-per-turn policy. The Api exposes exactly what a
champion can observe: its own vision plus its own ward (and tiles revealed by
its failed moves this round), shared and draft memory, and the static map
(`api.map()`, which real bots read once at startup). Out-of-vision queries
return the engine's errors (97 etc.).

Building blocks shared with the real bot (bitboards, shadowcasting, distance
fields, map decoding) are plain C++ with no simulator dependencies beyond
`core.h`, so the same code can be compiled into the submission.

## Fuel

- Budget per bot instance per turn: 100,000 for C++ (`FuelBudget`), x10 on a
  draft bot's first turn, x2 on a champion bot's first turn; nothing carries
  over.
- Every Api call is charged through a `PriceTable` (`base + per_n * n`, where
  `n` is a call-specific size such as records returned, or a custom
  function). Prices are **measured against cambc** (`docs/FUEL.md`):
  most host calls cost 1-30 fuel, board-sized ones about one fuel per 8x8 chunk,
  and host geometry is priced by its actual work.
- A policy charges its own computation with `api.compute(fuel)` (or by using
  the priced geometry wrappers `api.distance_field`, `api.shadow_cast`,
  `api.reachable`).
- When a charge overruns the budget the bot is **suspended inside that call**
  (its coroutine yields); it resumes at its next turn with the overrun carried
  into the new budget, and only then does the call take effect. This mirrors
  Wasmtime fuel exhaustion in the real engine. `MatchStats::suspensions`
  counts these.
- `MatchOptions::unlimited_fuel` disables enforcement (charges are still
  counted).

## Python

```python
import cambsim
m = cambsim.load_map("maps/00elkring.map26a")

class Mine(cambsim.Player):
    def turn(self, api):            # once per turn; api.champ == -1 for the draft bot
        ...                         # api.champion(h) -> (err, ChampionInfo), api.move_to(x, y) -> (err, ok), ...

r = cambsim.Match(m, Mine(), cambsim.builtin_player("starter")).run()
rs = cambsim.run_matches(["maps/00elkring.map26a"], "starter", "starter", games=64, threads=8)
```

Queries return `(err, value)`, actions `err` or `(err, ok)`; masks are numpy
`bool[H, W]`. `run_matches` plays built-in C++ policies on a thread pool with
the GIL released. Python policies run as *inline* players: they cannot be
suspended mid-call, so a charge that overruns the budget raises
`cambsim.FuelExhausted`, which ends the turn (the call does not happen;
`truncations` counts these). This is the one deliberate deviation from the
engine's fuel semantics and applies only to Python policies.

## Differential testing against cambc

1. `oracle/setup_workspace.sh` installs cambc and its toolchains into `~/ws`.
2. `oracle/run_trace.py MAP|all SEED... --jobs N` builds the tracer bot
   (`oracle/bots/tracer`: a seeded semi-random policy that exercises every
   action and logs every observation and action result), plays it against
   itself in cambc, merges both teams' logs into global turn order
   (`oracle/tools/make_script.py`) and runs `sim/build/replay` on the result.
3. `replay MAP SCRIPT` re-issues each recorded action through `cbs::Api`
   and regenerates every observation with identical formatting, reporting
   each mismatching line (with resync), the final result vs cambc's, and
   diff counts by kind. `--watch-camp`, `--watch-group` and `--watch-champ`
   print internal state for chosen rounds when chasing a diff.

Status (Oct 2026): seeds 11, 12, 13 and fuzzed seeds 100, 101 on all 40 pool maps and seeds 1-4 on
00elkring replay with **zero diffs** (about 0.5-1.2 M observation lines and
14-32 k actions per game) and identical final results. Remaining unconfirmed
rules are marked `RULE?` in the code.

## Performance

Single thread, `-O2`, one game = full draft + up to 2000 rounds:

| Matchup | Map | 1 thread | 4 threads |
| --- | --- | --- | --- |
| idle vs idle (engine floor) | 00elkring (30x30) | 270 | |
| starter vs starter | 00elkring | 31 | 104 |
| starter vs starter | 01big-world | 4.5 | 19 |
| starter vs starter | all 40 pool maps, round robin | | 50 |

(4-core container, `bench`; games/s for full games including the draft.)

With the starter policy most time is the policy's own distance fields; the
engine itself (vision, rules, Api) is a few percent. `run_matches`/`bench
--threads T` scale across cores (one match per thread, no shared mutable
state). The hot loop does not allocate: vision comes from per-tile windows
(computed on a tile's first use and shared by every match on the map), cached per
Api by (round, position, ward, reveals).

Speed work (genome/simspeed, Oct 24) made genome_eval 2.2-2.4x faster with
bit-identical results. With the bot memo in play (genome and .pol sides), most of
the remaining time is breadth-first search: the memo's pricing searches, the
simulator's own answers and the genome's fields, about 25% (40% on 100x100 maps),
all in `bfs_layers` (bitboard.h). Any change that could alter a result must pass
`genome/tools/exact_suite.sh BASE_REV`. It plays the same 880-game suite with both
binaries (genome, .pol and starter sides, both teams, all maps, --bot-seeds) and
compares every game, including a hash of each team's per-turn fuel
(`genome_eval --details --fuel-hash`; `GENOME_TURN_FUEL_ALL=DIR` dumps it all).
